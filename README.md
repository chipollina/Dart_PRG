# Лабораторная работа №7. Углублённое ООП в Dart — RPG-битва
Консольная RPG-битва на Dart, демонстрирующая наследование, абстрактные классы, переопределение методов и полиморфизм.

**Автор: Домрачева Полина**
**Группа: ИСП-241**

## Запуск
1. Клонировать репозиторий: `git clone https://github.com/chipollina/Dart_PRG.git`
2. Перейти в папку: `cd Dart_PRG`
3. Установить зависимости: `dart pub get`
4. Запустить: `dart run`

## Что изучила 
1. Наследование классов через extends и вызов родительского конструктора через super(...).

2. Абстрактные классы и абстрактные методы: Character нельзя создать напрямую, наследники обязаны реализовать attack() и toString().

3. Переопределение методов (@override), включая частичное переопределение с вызовом super.takeDamage(...).

4. Полиморфизм: функция fight(Character, Character) работает с любым наследником, а нужный attack() выбирается во время выполнения.

5. Инкапсуляция: приватные члены библиотеки через _ (например, _random).

## Ответы на вопросы 
1. Что такое абстрактный класс? Почему нельзя написать Character() напрямую?
Абстрактный класс - это шаблон, который не предназначен для создания экземпляров. Он описывает общую структуру для наследников. Написать Character() нельзя, потому что класс помечен abstract - компилятор запрещает его прямое создание, так как у него есть методы без реализации (например, attack()), и объект был бы неполноценным.

2. Зачем нужен super в конструкторе наследника? Что будет если его убрать?
super - ссылка на родительский класс. super(name: name, hp: 120) вызывает конструктор родителя с именованными параметрами. Без этого вызова конструктор родителя не будет выполнен, и поля, которые он инициализирует (включая maxHp = hp), не получат значений.

3. В чём разница между @override у attack() в Warrior и takeDamage() в Warrior? Почему второй переопределяет метод который уже имеет реализацию в 
родителе?
attack() в родителе - абстрактный метод без тела, и наследник обязан его реализовать. takeDamage() в родителе уже имеет реализацию, но Воин переопределяет его, чтобы изменить поведение: броня уменьшает каждый удар на armor единиц, после чего вызывается super.takeDamage(reduced) - метод родителя с уменьшенным уроном.

4. Функция fight(Character a, Character b) не знает кто реально придёт — 
Warrior, Mage или Archer. Как называется эта концепция и где вы её уже видели 
во Flutter?
Это полиморфизм: переменная типа родителя может хранить объект любого наследника, и вызов attack() сработает для того класса, который реально лежит в переменной. Во Flutter так же работает Widget build(): он принимает и возвращает Widget, но реально там может лежать Text, Column, ElevatedButton - любой наследник.

5. Что означает _random с нижним подчёркиванием в классе Character?
Нижнее подчёркивание делает поле приватным на уровне файла. К нему нельзя обратиться из другого файла напрямую (только внутри lib/character.dart). Это инкапсуляция: генератор случайных чисел является внутренней деталью реализации и не должен использоваться снаружи.
